## 3. 栈、队列和数组

### 3.1 栈
---
#### 3.1.1 栈的基本概念

**栈的基础概念**

- **栈**：栈是仅允许在一端进行插入和删除操作的线性表。
- **栈顶**：允许插入删除的一端。
- **栈底**：固定不变、不允许插入删除的一端。
- **空栈**：不含任何元素的栈。

**栈的基本操作**

- **InitStack(S)**：初始化一个空栈S。
- **StackEmpty(S)**：判断栈是否为空。如果栈S为空，返回true；否则返回false；
- **Push(S, X)**：入栈操作。
- **Pop(S, X)**：出栈操作。
- **GetTop(S, *X)**：获取栈顶元素，赋值给X。
- **DestroyStack(S)**：摧毁栈S。

**栈的数学性质**
>当n各不同元素按固定次序入栈后，可能的出栈序列总数为$\frac{1}{n+1}C^{n}_{2n}$

#### 扩展（指针释放和置NULL）

**1. `free` 到底做了什么**

- `free(P)` 的含义是：把 `P` 指向的那块内存**还给本进程的堆管理器**（malloc/free 的簿记系统），让它以后能再分配给下一次 `malloc`。
- `free` **不会**做三件事：不清零内存内容、不改变 `P` 的值、不阻止你再访问。
- 所以 `free(P)` 之后，`P` 里存的地址**原封不动**，仍然指向那块已经"退租"的内存 —— 这种指针叫**悬空指针（dangling pointer）**。

**2. 悬空指针的危害（use-after-free）**

`free` 后继续通过 `P` 读写，语法上允许、编译器不拦，但属于**未定义行为（UB）**。那块内存可能有三种命运：

1. 暂时没人要 → 读到旧数据，看似"正常"（最坑，掩盖 bug）；
2. 被下一次 `malloc` 拿走 → 你一写就**覆盖了别处的数据**，悄悄埋雷；
3. 整页被系统回收 → 一访问就**段错误崩溃**。

结果不确定，所以标准定义为 UB。

**3. 什么时候要置 NULL，什么时候不用**

核心判断：**`free` 之后，这个指针后面还会不会被读或被再 `free`？会 → 置 NULL；不会 → 省了。**

| 情况 | 是否置 NULL | 原因 |
|------|:----:|------|
| 结构体成员指针、全局指针、生命周期长的指针 | ✅ 要 | 后面可能再访问，防悬空 / 防 double free |
| `free` 后立刻 `return` 的局部指针 | ❌ 不必 | 出作用域自动消失，置了也白置 |
| `free` 形参后改形参本身 | ❌ 无效 | 改的是地址的副本，不影响调用方 |

> 补充：置 NULL 只是**一条赋值指令**，成本近乎为零，若指针马上出作用域编译器还会优化掉。所以作为默认习惯**推荐**：近乎零成本，能防住"同一指针"的 use-after-free 和 double free。

**4. `free` 影响的范围：进程隔离，线程共享**

- **其他进程**：❌ 影响不到。每个进程有独立虚拟地址空间，别的进程看不到也碰不到你的内存。
- **同进程其他线程**：⚠️ **会**。同进程所有线程**共享同一个堆**，你 `free` 掉的内存可能被别的线程 `malloc` 拿走，此时用悬空指针写就会踩它的数据（多线程 use-after-free）。
- 注意：`malloc`/`free` **本身是线程安全的**（内部有锁），但这只保证分配器簿记不乱，**拦不住你写的 use-after-free 逻辑错误**。

**5. Double Free（同一块内存 free 两次）**

```c
int* P = malloc(sizeof(int));  // P = 0x10
free(P);                       // 第一次，0x10 还给堆管理器
free(P);                       // 第二次 —— Double Free，UB！
```

- **危害**：破坏堆管理器内部的空闲链表等簿记结构，轻则 `double free or corruption` 崩溃，重则被攻击者利用做**任意内存写**（堆利用，CTF 经典）。
- **别名版本更隐蔽**：`int* Q = P; free(P); free(Q);` —— `Q` 和 `P` 存同一地址，也是 double free。

**6. 置 NULL 为什么能防 Double Free**

关键点：**`free(NULL)` 是安全的空操作**。

```c
free(P);
P = NULL;   // 关键
free(P);    // 此时 P 是 NULL，free(NULL) 什么都不做，安全
```

⚠️ 但**只能防"同一个指针"重复 free**：别名 `Q` 仍指向原地址，`free(Q)` 照样 double free。别名问题必须靠**理清所有权**解决。

**7. 小结口诀**

> **谁 malloc 谁负责 free；free 完顺手置 NULL；别名各自管好；拿不准上 valgrind / ASan。**
>
> 一句话：`free` 退租的是"内存"不是"指针"；指针里的旧地址不变，谁拿着它访问都是 UB。置 NULL 是主动抹掉旧地址、断掉误用与重复释放的兜底手段，但管不了别名。

#### 3.3.2 栈在表达式求值中的应用

1. **算术表达式**：
    - 中缀表达式：3 + 4
    - 前缀表达式：+ 3 4
    - 后缀表达式：3 4 +
    >中缀符合人们阅读习惯，但是前缀和后缀适合机器运算。
2. **中缀表达式转后缀表达式**：

    1. 手算转换方法：

    - 按照运算优先级对整个表达式逐层加括号。
    - 将每个运算符移到其所在括号的右边。
    - 将所有括号去掉。
    > 王道数据结构 Page 91有详细说明

    2. 计算机转换方法
    - 遇到**操作数**：直接加入后缀表达式。
    - 遇到**界限符**：若为"("，直接入栈。若为")"，不入栈，且不断弹出栈顶运算符并加入后缀表达式中，直到遇到"("，然后将其弹出丢弃。
    - 遇到**运算符**：若其优先级高于栈顶运算符，则入栈。若其优先级低于等于栈顶运算符，则出栈，直到栈空或者栈顶为"("或者遇到优先级更低的运算符。

    > 王道数据结构 Page 91有详细说明

    [中缀表达式转化为后缀表达式的方法](../DSAA_Code/ch3/3_3_2栈在表达式求值中的应用.c)


3. **后缀表达式求值**：

**后缀表达式求值过程**：从左向右扫描表达式，如果为操作数，则入栈，如果为操作符，则从栈中弹出两个操作数，与运算符进行运算，然后将计算结果压入栈中。扫描完毕之后，栈顶元素就是计算结果。
